도란도란 시스템 지도

부모 목소리로 동화를 읽어 주는 서비스가 지금 어떻게 돌아가는지. 앱은 API에만 말을 걸고, 녹음과 생성된 소리는 S3 서명 URL로 직접 오가며, GPU 작업은 디스패처가 Modal에 맡긴다. 구성요소·S3 버킷을 누르면 설명이, 아래 흐름의 단계를 누르면 경로가 켜지고 오른쪽에 그 단계의 상세 설명이 나온다.

핵심 흐름

    지금 알아 둘 것

    한 곳에서 둘이 돈다. 개발자 PC(로컬 API 3100 + Docker MariaDB)와 공용 dev 서버(EC2 1대)가 같은 S3 dev 버킷과 같은 Modal 앱을 쓴다. DB만 따로다.

    EC2는 검증용이다. 운영 구성(도메인·HTTPS·사설 DB)은 다음 단계다.

    GPU는 쓸 때만 뜬다. Modal 서버리스 T4, 동시 1대, 유휴 60초 뒤 종료. 첫 작업은 컨테이너가 뜨는 시간이 붙는다.

    성우 낭독은 실제 녹음이다. 동화 8편은 녹음을 Modal에서 받아쓰고 EC2 컨테이너에서 문장별로 잘라 넣었다. 기계 합성(Supertonic 3)은 2026-11-07 제거.

    점선 상자는 아직 없는 것. 그림 엔진(초기 스튜디오가 PC에서 쓰던 ComfyUI — Modal로 옮길 예정), BGM·효과음(선택), CDN(운영 전환 때). 연결 방법은 각 상자를 눌러 보기.

    스튜디오는 API만 본다. 브라우저에서만 도는 정적 페이지(11-13부터 스튜디오 서버 없음). 원고·검수·발행은 MariaDB(/admin/studio), 파일은 S3, 낭독·받아쓰기·그림은 Modal 작업. 원고 규칙(검사·미리보기 계산)도 API가 원본을 갖고 브라우저에 내려 준다(GET /studio/rules, 이슈 113). 발행 내용·그림 그래프·Claude 장면 연출은 API가 만든다 — docs/studio-client-split.md.

    계약은 api-spec. 작업 페이로드(§11)·타임라인 단어 {w, s, e}를 Worker와 앱이 함께 지킨다.
